# 암호화

암호화란 데이터를 제3자가 해독할 수 없는 상태로 변환하는 것입니다. 텍스트 데이터는 암호화하면 의미를 알 수 없는 문자열로 바뀝니다. 이때 사용된 계산 방법과 키를 알고 있다면 암호화된 데이터를 원래 데이터로 되돌릴 수 있습니다.

암호화 처리 절차나 계산 방법을 **암호 알고리즘**이라고 하며, 알고리즘 계산에 사용하는 특정한 부호(수치 데이터)를 **키**라고 합니다. 알고리즘이 알려져 있더라도 키가 없으면 복호화할 수 없습니다. 즉 암호의 기밀성은 알고리즘이 아니라 키로 유지됩니다.

암호 기술은 키의 특성에 따라 크게 **공통키 암호화 방식(비밀키 암호화 방식)**, **공개키 암호화 방식**, **해시 함수** 세 가지로 나뉩니다. 이 중 앞의 두 가지가 복호화가 가능한 암호화 방식이고, 해시 함수는 되돌릴 수 없는 단방향 함수입니다.

## 해시 함수

해시 함수는 원본 데이터에 일정한 처리를 하여 고정된 길이의 결과를 출력하는 함수입니다. 앞의 두 방식과 달리 암호화에 사용하는 키가 없으며, 키로 복호화하는 것도 불가능합니다. 알고리즘상 난수나 특별한 파라미터를 사용할 수는 있지만, 그것을 알아도 원문을 해독할 수는 없습니다.

입력은 길이 제한이 없는 반면 출력은 고정 길이이므로, 서로 다른 평문이 같은 해시 값을 갖는 경우(충돌)는 반드시 존재합니다. 다만 그런 쌍을 찾아내거나 해시 값으로부터 평문을 역산하는 것이 계산적으로 불가능에 가깝다는 점이 해시 함수의 안전성을 뒷받침합니다.

이런 특성 때문에 비밀번호 저장이나 데이터 변조 방지에 이용됩니다. 같은 데이터에서는 반드시 같은 해시 값이 출력되므로, 입력값을 해시 함수로 처리한 결과가 등록된 값과 일치하는지 여부로 검증합니다.

다만 이 결정적인 성질은 비밀번호 저장에서는 약점이 됩니다. 같은 비밀번호를 쓰는 사용자들의 해시 값이 모두 같아지기 때문입니다. 그래서 사용자마다 다른 임의의 값인 **솔트(salt)** 를 원문에 덧붙여 해싱하여, 같은 비밀번호라도 저장되는 값이 서로 다르게 만듭니다.

## 공통키 암호화 방식

암호화에 사용하는 키를 송신자와 수신자가 양쪽에서 비밀리에 공유하여 암호화 통신을 수행하는 방식을 공통키 암호화 방식이라고 합니다. 하나의 키로 암호화와 복호화를 모두 처리하므로 구조가 단순하고 처리 속도가 빠릅니다.

문제는 그 공통키를 어떻게 안전하게 공유하느냐입니다. 네트워크를 통해 키를 주고받는 과정에서 유출될 위험이 있고, 이 위험은 방식 자체에 내재해 있습니다.

## 공개키 암호화 방식

반면 암호화 키와 복호화 키를 나누어 암호화 통신을 수행하는 방식을 공개키 암호화 방식이라고 합니다. 송신자는 수신자가 공개한 공개키로 원본 데이터를 암호화하여 전송하고, 암호화된 데이터는 수신자가 가진 개인키로만 복호화할 수 있으므로 암호화 통신이 성립합니다.

암호화와 복호화에 사용하는 키가 다르기 때문에, 복호화에 쓰이는 개인키만 본인이 보관하면 공개키는 네트워크로 전송해도 문제가 없습니다. 공통키 방식의 키 공유 문제를 해결한 지점이 바로 여기입니다.
